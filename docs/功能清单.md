# 内保合规审核台：改版前功能清单

> **基线日期**：2026-10-04  
> **范围**：本文件按现有源码逐项记录网站功能、交互和统计口径，仅用于后续视觉改版的功能回归。没有修改任何审核条目、数据结构、计算、自动复核、导入导出、本地保存或状态管理。

## 1. 产品边界与数据基线

- 产品名称：**内保合规审核台 · 单位内部治安保卫全标准版**。
- 审核依据：DB11/T 2552—2026 第 1—9 章与附录 A—H；2004 版《企业事业单位内部治安保卫条例》；修订征求意见稿仅作前瞻参考。
- 数据仅保存在浏览器本机（`localStorage`）；界面提示“不上传材料”。
- 当前归档的固定回归样例：`baseline/sample.json`；预期显示数值及导出结构：`baseline/expected.json`。
- 审核主模块：适用性与单位画像、责任制与组织、人员与岗位、制度与档案、风险评估、一般单位常态防范（第5章）、重点单位常态防范（第6章）、非常态防范、系统技术、应急处置、检查整改、附录与交叉验证。

## 3. 顶部栏、侧栏和全局按钮

| 控件 | 行为 | 校验/提示 |
|---|---|---|
| 保存图标 | 用当前画像、全部答案和当前时间调用本机保存 | 浏览器存储失败时暂停自动保存、显示持久化异常并提示立即导出 JSON |
| 导入 | 只接受 `.json` / `application/json` 文件 | 文件经版本、字段类型、日期、枚举、文本长度、条目 ID 与原型键防护校验；失败不改变当前审核 |
| 导出 JSON | 导出完整档案及 A04 控制元数据 | 文件名为“单位名-内保审核.json”；无名称时使用“单位” |
| 恢复横幅的“导出原始草稿” | 导出无法恢复的原始本机内容 | 仅在本机恢复发生异常时显示 |
| 恢复横幅的“导出当前草稿” | 导出当前内存中的有效档案 | 仅在本机保存异常时显示 |
| 左侧导航 | 审核总览、分模块审核、整改清单、依据与差异、审核报告 | 整改项角标为 `currentScore.remediationOpen.length`；当数值为 0 时不显示角标 |
| 清空本地数据 | 清空浏览器本地档案 | 确认文案为“将清除本浏览器中保存的所有审核数据，建议先导出 JSON。”；提供“取消 / 清除”和“先导出JSON”，失败时不清空并提示先导出 JSON |

## 4. 单位画像：字段、选项与创建规则

### 4.1 基本字段

| 字段 | 控件/选项 | 保存校验或默认行为 |
|---|---|---|
| 单位名称 | 文本 | 可为空；用于页面标题与导出文件名 |
| 所属地区 | 文本 | 可为空 |
| 单位类型 | 下拉：企业、事业单位、机关、社会团体、其他单位 | 必须是预设枚举 |
| 所属行业 | 文本 | 可为空 |
| 审核人 | 文本 | 可为空 |
| 审核创建日期 | 日期 | 新建/重置审核时默认中国时区当天；必须是有效 `YYYY-MM-DD` 日期；编辑旧档案保留已有日期 |
| 多地机构、设施或场站 | 勾选 | 影响部分适用性 |
| 按重点单位模式审核 | 勾选 | 未选中时第6章以“资格筛查入口”显示；选中后显示防范级别 |
| 重点单位防范级别 | 下拉：未确定、三级、二级、一级 | 仅重点单位模式显示；选“未确定”后会触发相应人工复核 |

### 4.2 专项场景与 A04 高级筛选

- 专项场景折叠区：涉及国家秘密/涉密载体、危险物品/菌种/武器弹药、人员密集/大型活动场所、重要数据存储/重要高科技或互联网业务。勾选会触发专项适用性与资格复核，**不会**自动变更为重点单位模式。
- A04 高级筛选折叠区用于精确排除确定不涉及的原子控制，不是创建审核的必填项：工程/高风险项目、工程/运行阶段、公共视频场所类型，以及报警、视频、门禁、巡查、停车、安检、个人信息、人脸识别、涉密毗邻、地下连通、进气口、门卫室门、特殊门库房、共用建筑、监控中心、网络运营者等事实。
- A04 事实默认“未核实”；只有记录“明确不涉及”时，条件控制才可能被排除。保存画像自动关闭弹窗。
- “重置审核答案”仅重置答案，关闭弹窗并返回总览；“取消”不保存草稿。

## 5. 审核总览

### 5.1 显示内容与按钮

- 显示当前审核日期、单位名称、创建/编辑审核按钮。
- 三张指标卡：现行基线完成率及风险等级/关键缺口，待整改及关键项数，附录 F “宜”建议得分及建议项数。
- 逐模块卡片显示当前国内适用项数量和已审核比例；点击进入对应模块。
- 非重点单位模式下显示“第6.1重点单位类别筛查入口”，可点击查看第6章。
- 页面底部审核提示及“查看第6章”按钮。

### 5.2 总览统计口径

- 完成率分母为 `current.counted`：**国内强制项**，排除“宜”建议项、有效“不适用”项和被 A04 原子控制替代的旧父项。
- 模块卡片和“国内适用审核项”使用 `current.domestic`：所有当前国内适用项，包含建议项和仍会被计分去重的旧父项；不包含国际补充项。
- 模块“已审核”以原始状态为符合/部分符合/不符合/不适用计数；未审核不计入完成数。

## 6. 分模块审核页面

### 6.1 页面级控件

| 控件 | 行为 |
|---|---|
| 模块导航 | 切换当前模块；左侧显示该模块在审核页集合中的条目数 |
| 返回总览 | 返回审核总览 |
| 显示/隐藏补充核验 | 切换 `profile.a04.showSupplemental`；国际方法补充保留在档案/导出/整改范围，但不计国内合规分 |
| 搜索框 | 按条款编号、标题、要求和依据条款实时筛选当前模块 |
| 重点单位入口 | 非重点单位模式下，提示第6.1筛查；“展开重点单位模式”将重点模式设为启用且防范级别为未确定 |

### 6.2 每个普通审核项

- 显示：条款编号、标题、前瞻依据标记、关键项标记、A04 来源标记、权重/建议项/补充项说明、审核要求、依据。
- 结论按钮：**符合、部分符合、不符合、不适用**。
- 证据与整改字段：证据编号/位置、整改负责人、整改期限、整改措施；选择“不适用”时额外显示必填样式的“不适用理由”。
- 补充项结论和整改会保留，但不会改变国内得分、分母、关键缺口或国内风险结论。

### 6.3 A04 原子控制展开区

每个 A04 控制包含以下信息和输入：

- 控制适用条件、最低证据、责任部门、关闭条件；对象/空间点位、适用/排除判断理由、来源适用说明。
- 有结构化规则时：实测值、实测单位和结构化判定结果。
- 期限/频率来源、整改期间临时防范、待专家/人工复核原因、不适用依据、复核证据、复核人员、复核日期、关闭日期。
- 逐来源适用与结论：每一来源可分别选择待判断/适用/排除，分别记录结论、理由和证据。
- 子断言：可添加、编辑和删除；每个子断言有名称、结论、证据、整改。任一适用子断言未审核/部分符合/不符合可覆盖父项的“符合”。
- 若用户选择的结论会被结构化指标、逐来源核验、子断言或不适用规则改变，页面显示“有效结论”警示。

## 7. 自动复核、有效结论与整改角标逻辑

### 7.1 人工复核提示

下列原因会进入“需人工复核”提示，并在报告的人工复核明细中导出：

1. 重点单位模式开启但防范级别未确定。
2. 画像包含涉密、危险物品、人员密集或重要数据等专项场景。
3. 已选“不适用”但没有填写任何理由。
4. A04 适用控制使用禁止的“未安装/未设置”式理由，或在不得不适用的控制上选择“不适用”。
5. 缺少负责人、期限、措施、临时防范、复核证据、复核人员或复核日期却标记为“已关闭”的整改。

### 7.2 有效结论与整改关闭

- A04 控制的有效结论会检查不适用依据、结构化规则、子断言和逐来源适用/结论；点击“符合”不必然等于用于计分和报告的有效“符合”。
- 整改关闭前必须补齐负责人、期限、措施、整改期间临时防范、复核证据、复核人员和复核日期；关闭不改变原合规结论。
- 侧栏整改角标采用当前基线的 `remediationOpen`：国内缺口、建议项缺口及国际补充缺口中，未关闭或关闭证据不足的项目数。
- 整改页先按前瞻全量适用项取得“部分符合/不符合”缺口，再按“全部/待整改/整改中/待复核/已关闭”和“立即/高/中”筛选；“回到审核项”定位到所属模块。

## 8. 依据与差异页面

- 显示 DB11/T 2552—2026 第1—9章、附录A—H的条款索引总数，以及现行标准、规范性引用文件、使用提示三张信息卡。
- 可搜索条款号、章节、设施或关键词；可按全部/规范性/资料性附录/术语定义/规范性引用筛选。
- 按章节展示索引数量，逐条显示编号、类型、章节、标题、要求和来源。
- 显示法规口径提醒：DB11/T 2552—2026是主基线；2004版条例提供责任/机构/制度映射；征求意见稿仅前瞻参考，不改变现行基线分数。

## 10. JSON 导入、兼容与本机保存

- 当前档案版本为 **5**；导入仅接受 1 至 5 的显式支持版本，保存时统一输出当前版本和当前 A04 控制集版本。
- 导入校验包括：最大 1 MiB、合法 ISO 时间/日期、已知单位类型/状态/重点等级/A04枚举、长度限制、审核项 ID 白名单、禁止 `__proto__`/`constructor`/`prototype` 键、A04 子断言/逐来源明细结构。
- 旧档案可迁移至当前默认条目；新增 A04 原子控制不会被自动推定为“符合”。
- 标为已关闭但关闭证据不完整的导入整改，会降级为待整改并保留说明。
- 自动保存有 800 ms 延迟；保存失败时，当前页面内存草稿保留并提示立即导出。

## 11. 用户提出的计数差异说明（不修改计算）

### 11.1 “总览 221 个适用审核项”与“报告 国内适用项目 182”

这是**两个不同的现有统计集合**，不是同一个分母：

| 页面文案 | 代码集合 | 包含/排除 |
|---|---|---|
| 总览“国内适用审核项” | `current.domestic` | 全部当前国内适用项；包含建议项，也保留会被原子控制替代的旧父项；排除国际补充项 |
| 报告“国内适用项目” | `current.counted` | 仅强制项；排除建议项、有效“不适用”项，并对被 A04 原子控制覆盖的旧父项去重 |

在本基线样例的单位画像、**尚未填入两条“不适用”答案前**，上述集合分别是 **221** 和 **182**。样例刻意留下 S-01、G-02 两条无理由“不适用”，因此报告最终计分分母为 **180**，并触发“缺少不适用理由”的人工复核。这是样例覆盖校验的预期结果，未改动任何计算。

### 11.2 “责任制模块总览 16、审核页 17”

两个页面的模块集合确实可不同：总览按 `current.domestic` 统计；审核页按 `forwardScore.active` 统计，并受“显示补充核验”开关影响。因此，前瞻专用项或展开补充项时，审核页可多于总览。

但对**当前归档的同一基线样例**（补充核验关闭），责任制与组织模块实际都是 **17** 项；“16/17”并不能由该同一画像和同一开关状态复现。该历史观察值至少意味着当时使用了不同的单位画像、补充核验开关或不同构建版本。此处只记录现状和差异来源，**没有调整任何条目或计算**。

## 12. 基线回归命令

```bash
npm run check
```

该命令依次执行 TypeScript 检查和基线回归：导入 `baseline/sample.json`、读取总览/审核页/整改页/报告页的关键统计并与 `baseline/expected.json` 对比、验证 JSON 精确导出往返及 Word/Excel 内存文件生成。它不启动浏览器，不写入 `localStorage`，也不改写样例文件。
